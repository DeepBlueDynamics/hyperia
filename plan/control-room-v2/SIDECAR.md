# Sidecar architecture — Codex

Status: research/design, 2026-09-24. No product code changes or Hyperia build. One synthetic Node framing benchmark is reported below; end-to-end and Rust CPU measurements remain unrun. Arithmetic and acceptance budgets are labeled separately.

## Verified baseline

`hyperia-ref/stream.rs::wall_loop` creates a per-viewer interval, scans sessions, calls `screen_dump()` inside the `sessions().await` snapshot scope, then exits that scope before socket awaits. Each viewer owns a full comparison cache. `pane_raw_loop` obtains a formatted seed before subscribing to live output: do not copy that seed/subscribe gap. It polls dimensions every 200 ms. `pixels_loop` polls Electron CapturePane, then hashes JPEG bytes. `tab_loop` independently polls and captures. These are the supplied implementation, not all promises in EVENT_STREAM_API.md. The director describes this accessor as a session-table mutex; its concrete accessor implementation is not in the supplied source, so verifying actual lock duration remains a host-source prerequisite.

`hyperia-ref/screen.rs::process` only delegates to vt100. There is NO mutation damage API in this wrapper. `diff()` dumps the complete screen and compares text only; it misses attribute-only row changes and has one shared last_snapshot. `screen_dump()` allocates strings and formats debug colors per cell. Do not reuse it per frame or call its destructive diff for multiple viewers. `bridge.rs` was not supplied: existing fan-out capacity, overflow and ingest ordering must be checked in the host source before claiming a safe implementation.

## Committed boundary

Add `sidecar/src/room/{mod,model,leases,ingest,damage,protocol,pacing,stream,persistence}.rs`, and `GET /ws/room/{id}` in the sidecar router. Rust owns room entities, tagged bindings, geometry, pane placement/composition commands, lease aggregation, focus, revisions, simulation and publication. Client owns camera presentation, picking intents and GPU drawing. Composition means authoritative Rust placement of cell surfaces; no server wall pixel framebuffer. New room clients stop using timer-polled `/ws/wall`; preserve v1 compatibility for external users rather than silently changing its wire contract.

Use binary cells for terminal wall AND desk surfaces. There is one terminal state producer per unique watched pane, shared by all surfaces/viewers; no independent desk VT parsing. Source union is Empty | Pane | Tab | Static | WebCapture; desk destinations and control intents are separate types. Retired terminal-prefix/catalog seeds do not return. Raw `/ws/pane` remains the external xterm reference, not room desk transport. WebCapture uses a new lossless PNG capture path, watched and damage-triggered, at most2x1920x1080 sources with10Hz cap (uncompressed upper bound165.888MB/s), separate from terminal4K60 qualification. No JPEG for text-bearing pages. Inadequate lossless capture must be shown as unavailable until implemented, never silently treated as cells. See PLAN revision3.

## Literal zero added work while unwatched

Choose a viewer-scoped room mirror fed by the EXISTING `Bridge::subscribe_output` fan-out. No added call, atomic counter, damage branch, allocation or notification in `bridge.rs` SessionData when no room viewer exists. First effective lease creates one receiver and one room-owned parser per pane; last effective lease removes receiver and destroys parser, mailbox and scheduled deadline. Reuse existing parse semantics in a room-specific parser implementation with dirty-row mutation tracking; do not change the normal ScreenBuffer process path. Extra parsing while watched is a conscious CPU cost, measured as room overhead. This is the price of the literal zero-added-ingest-work requirement; do not conceal it in the baseline.

Fan-out sends must be nonblocking and byte-bounded. Existing bridge source must establish that before coding; if its subscriber implementation needs bounding, change the existing subscriber send implementation, not add a second room publish hook. With viewers attached, existing fan-out does one bounded enqueue/reference handoff per pane chunk independent of viewer count. Producer never waits for room/network/GPU.

Add a control-plane atomic subscribe-and-seed operation under the SAME serialization that orders ingestion: install receiver and copy parser state at one boundary, then release guard. Cloning parser state is preferred over formatted text because a formatted screen does not include incomplete escape-sequence parser state. Seed has a stream generation, dimensions and sequence boundary. No await between subscribe and seed under that guard. Resize/close/topology events enter the same ordered subscription from existing lifecycle arms (not per-byte polling). If actual bridge locking cannot support the boundary, that is an implementation blocker, not permission to use a racy seed. A receiver overflow destroys its parser and reseeds; dropping raw bytes and continuing to parse is forbidden. Explicit implementation commitment: vendor the vt100/vte parser as needed to export/import a full parser snapshot, including incomplete CSI/OSC/UTF-8 state, and instantiate the watched mirror with mutation hooks. Antigravity reports upstream vt100::Parser lacks Clone; no existing Clone API is assumed. Formatted screen bytes are insufficient and are rejected as the bootstrap solution. Compile the ordinary parser with a no-damage policy and the room mirror with a dirty-row policy; snapshot/restore is control-plane only. Verify no extra runtime branch/callback/instruction on unwatched normal ingest; the fork does not license hot-path overhead.

## Damage and refresh

Room parser mutation points mark bitset rows for text, fg/bg/attributes, erase, scroll, alternate-screen, wide-cell continuation and old/new cursor; resize/palette/font/epoch changes force keyframe. This requires a maintained parser adapter/fork with mutation hooks; ScreenBuffer::diff is not a substitute. Batch writes until a dirty-triggered one-shot deadline. No periodic scan or empty render tick. One deadline per active room, at most one outstanding wake. Events set damage; first damage arms next presentation deadline minus 2 ms, bounded to at most 4 ms coalescing wait in latency mode. On wake snapshot dirty rows and clear bits atomically in the room actor, encode once, publish immutable Arc buffers. If new damage arrives during publication, it belongs to the next generation and rearms once. Idle has no rendering timer (transport keepalive/lease expiry are separate low-rate lifecycle work).

Client maintains one pending requestAnimationFrame only while dirty, and reports presentation phase/ACK. At 60 Hz, full refresh period is 16.667 ms: arbitrary-arrival p99 phase wait alone is approximately 16.5 ms, before processing/scanout. Therefore a hard <=16 ms physical byte-to-pixel p99 requires >=120 Hz presentation qualification; run a separate 4K60 sustained-throughput test. Do not relabel requestAnimationFrame callback as a measured physical pixel change. Budget on >=120 Hz hardware: <=4 ms coalescing + <=1 ms room processing/wire + <=2 ms client/GPU + <=8.33 ms presentation phase = 15.33 ms target, with actual panel scanout/response still measured, not assumed. Stretch <=8 ms is not promised.

## Locks and ownership

Session-table lock is used only to resolve/copy owned handles or bootstrap a subscription. No guard escapes a lexical block, no `.await` under any session guard, no serialization/rasterization/file I/O under it. The steady-state room actor owns its mirrors and never scans or locks the session table. No nested room/session locks. Lifecycle events carry full canonical IDs and monotonically increasing epochs. Socket writer owns its sink and can await independently. Persistence batches revisioned room-state changes on a dedicated blocking worker, never on the frame/request path; no fsync per frame. Instrument session-lock hold p99 <=100 us for ordinary metadata operations; bootstrap separately budgeted <=1 ms/pane, not hidden in normal p99.

## Bounds and recovery

Per-pane raw receiver: 256 KiB byte cap, 16 KiB chunk cap (16 queued chunks maximum); overflow invalidates/reseeds mirror. These are implementation requirements, not verified existing bridge properties. Limit default room workload to 16 watched terminals x120x40, maximum 8 viewers. Per viewer allow one in-flight binary message <=2 MiB and one latest-state pointer plus dirty union; no delta FIFO. At most one ACK-outstanding frame. Never send a delta based on a discarded frame: when a pending base is lost, set needs_keyframe and send a current independent keyframe after outstanding ACK. A >100 ms missing ACK triggers resync state; >2 s missing ACK or stalled send closes socket. Explicit WebSocket write buffer <=2 MiB; application bound alone does not bound kernel/browser buffering. Client queues one latest frame and ACKs only applied generations. Lagged viewer cannot stall any producer or other viewer.

On resync, keyframe chunks carry epoch, total count and consistent snapshot revision; only swap client state when complete. On keyframe >2 MiB, chunk and bound one chunk in flight, never truncate. Reconnect full jitter 250 ms base, cap 8 s, resets only after successful snapshot. Room metadata updates are revisioned and authorization checked independently from read leases; terminal input retains existing terminal-control authorization per event.

## Numbers and tests

Arithmetic: a 120x40 grid with 16-byte cell records is 76,800 B; 16 panes are 1,228,800 B before headers/dictionary. Two dirty rows per pane are 61,440 B/frame =3.6864 MB/s at60; all rows at60 =73.728 MB/s. A full 4K RGBA image is33,177,600 B and 60Hz is1.991GB/s before encoding, 27x the cell payload for this grid. These are payload calculations, not benchmarks or universal compression claims.

Measured scratch evidence (2026-09-24): `node scratch/control-room-v2/cell-wire-bench.mjs`, Node v24.21.0, Linux x64 container, Intel Core Ultra9 285K (24 logical CPUs), 2,000 warmups +10,000 samples. Preallocated pack+decode for all16 panes: two-row frame61,984B median3.895us/p99 39.003us; full frame1,239,072B median95.539us/p99 668.621us. Process CPU across10,000 iterations69.482ms/1,347.408ms respectively. Established dictionary only; excludes VT/parser damage, allocations, socket, GPU and physical presentation. This is not a Rust CPU or end-to-end result. Rust check `rustc --version` failed because rustup has no configured default toolchain; no Hyperia build attempted.

CPU target <=1% of one core/pane means <=10ms CPU/sec/pane, or <=166.7us per60Hz publication including watched reparse, damage, encoding and fan-out. Reject the implementation if the raw-stream workload exceeds this; unlimited `yes` throughput has no finite universal CPU bound, so record actual ingress MB/s and chunk distribution. Idle/no-viewer differential must show zero additional ingest instructions by structural trace and no room wakes, not merely an averaged 0.0% display.

Tests required: atomic attach during split escape sequence, ordered resize under output, foreground/background-only damage, cursor-only change, erase/scroll/alternate-screen, Unicode combining/wide columns; two viewers at different speeds; forced raw overflow reseed; detach on every lifecycle path; poisoned slow socket does not delay other pane operations; bounded RSS for 10-minute slow-consumer run; 10-minute 4K60 render capture and physical latency trace. No such tests have run in this research document.

## Fidelity mandate — revision2

Fidelity wins speed ties. No bitmap8x8 fonts, lossy text frames or enlarged low-resolution glyph textures. Binary cells must preserve full grapheme strings/widths, RGB colors, all required attributes and cursor shape/blink/visibility; add lossless extension records for underline color/style. Supplied ScreenDump omits required fields, so it cannot seed authoritative v2 fidelity. Room-only parser must match xterm semantics, including partial-parser seed state; report any exact unsupported behavior rather than imply equality.

Client uses pinned vector fonts and browser raster settings matching reference xterm, density-keyed RGBA glyph atlas for color emoji, native-pixel per-surface GPU framebuffers and dirty updates. Mipmaps + >=8x anisotropic filtering qualify angled views; rerasterize before magnifying beyond1:1. Atlas budget changes from an R8 proposal to128MiB RGBA residency; one2048-square page with mips costs21.33MiB. Measure added GPU memory/mipmap costs honestly. No server rasterization remains the decision.

Every PLAN revision2 step now pairs its speed target with a fidelity check: zero unexplained native-view pixel differences vs pinned /ws/pane+xterm, exact field roundtrips, reference perspective transforms and legibility at ROOM-derived eye distances. Actual parity is not yet measured. A budget failure triggers optimization, never simpler fonts or omitted terminal state. JPEG compatibility cannot carry text-bearing content under this mandate; add a lossless capture path for those sources and measure separately.
