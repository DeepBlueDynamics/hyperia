# Control Room v2 — five-step implementation plan

Revision 3, Codex, 2026-09-24. Research deliverable only: no product implementation or Hyperia builds performed. Decisions are committed; performance numbers marked **calculated** are payload arithmetic, **budget** are acceptance targets, not achieved measurements. Fidelity takes priority over speed: no quality downgrade may satisfy a performance gate. Read SIDECAR.md for concurrency and lifecycle detail. Peer benchmark and votes pending; this revision does not claim consensus.

## 1. Put the room and composition authority in Rust

**Goal/deliverable:** one flat wall plus configurable desks, one authoritative Rust room actor. Own geometry, layout rectangles, stable object IDs, bindings, focus, power, lease aggregation, revisions and simulation in the sidecar. **Decision 1: client-drawn binary cells; Rust composes the layout and cell draw commands, client makes pixels.** No server framebuffer or Electron capture for terminal surfaces. **Decision 5: terminal desk monitors use the same composited cell protocol as terminal wall slots**, sharing one watched producer per pane; no second raw-PTY parser in the client. This explicitly chooses semantic composition in Rust rather than pixel composition. WebCapture is a separate, watched lossless pixel source for web panes, never parsed as terminal cells; see step3.

**Files/modules:** new Hyperia `sidecar/src/room/{mod,model,leases,persistence}.rs`, router/AppState integration in `main.rs`; migrate 3dterminal `descriptors/room-descriptor.ts`, `state/store.ts`, `surfaces/broker.ts`, room config and control intents. Move the backend scaffold simulation into a testable domain module; do not describe its synthetic telemetry as a completed SATCOM model. Bind any new listening server to `0.0.0.0`.

**Contract:** one wall display replaces three physical arcs. Preserve destination-local selection, independent power/binding, per-desk HUD and in-scene controls. Use Source = Empty | Pane{id} | Tab{id} | Static{id} | WebCapture{id}; IDs are canonical, never string-prefix discriminators. Surface identity and desk control intents are separate types, never sources. Mirrored desk/wall views refer to the same Pane ID. Current source migration strips retired terminal catalog bindings; do not restore the stale nav.solution/nav.route default from the August spec. Static images may be explicitly assigned by stable IDs and never enter the VT parser. Rust descriptor defines the initial layout; discovery cannot choose sources or slot count. Tab leases expand to their typed children. Desk height remains a numeric0.65–1.25m control bound. Keep camera presentation local, Rust state authoritative.

**Numbers/measurement:** budget 16 watched terminals x120x40, 8 viewer limit; initial 3 desks with 2/4/2 monitors, configurable in descriptor (ROOM lane may supply a justified revision). Idle/no-viewer has 0 room ingest callbacks, 0 stream subscriptions, 0 frame wakeups. Per-pane fixed cell state is **calculated** 76,800 B at16B/cell, all16=1,228,800B before dictionaries. Measure actor allocation/RSS and wake counters for60s idle and10-minute attach/detach churn. Persist on a blocking worker after state mutations, never frame/request fsync.

**Fidelity check beside speed:** freeze `/ws/pane` + xterm reference fixtures, fonts/theme, actual font files, browser build and devicePixelRatio before migration; package.json currently declares @xterm/xterm ^6.0.0, so pin the resolved version in the qualification harness. Every routed surface must preserve its reference content, independent power and layout across save/restore. Compare native front-facing screenshots pixel-for-pixel (0 changed pixels); legibility fixtures include the room's farthest seated eye and nearest desk eye, with required text angular size from ROOM.md. Stress-grid density never overrides a legibility failure.

**Risks/proof test:** legacy clobber bugs and multi-client divergent ownership. Replay all four prefix-clobber scenarios as tagged-source tests; two clients must observe identical revisioned state, power toggles must preserve source, desk actions must not change wall slots, and tab leases must vanish on detach. No render test currently proves these visually; step4 adds it.

## 2. Replace room polling with watched-only event-driven damage

**Goal/deliverable:** **Decision 2: room-owned dirty-row parser, fed by existing output subscription, coalesced by a dirty-triggered one-shot deadline.** `bridge.rs` SessionData receives no new room hook or damage check. First lease creates one mirror; final lease drops it. This spends extra parser CPU only while watched and is the literal zero-added-work solution while unwatched. Do not use current ScreenBuffer::diff (full dump, text-only comparison).

**Files/modules:** Hyperia `room/{ingest,damage,pacing}.rs`, a room-only parser adapter/fork with mutation hooks; add atomic subscribe-and-seed control operation around existing Bridge subscription, and ordered resize/close/topology lifecycle events. `screen.rs` normal process remains untouched. Verify unsupplied host `bridge.rs` first: the existing fan-out must be bounded/nonblocking and the seed boundary must share ingest serialization.

**Mechanics:** clone parser state (including partial escape sequences) and install receiver at one atomic ordering boundary; no seed→subscribe gap. Mark dirty rows on character/style/erase/scroll/wide-cell/cursor mutations; force fresh epoch for resize/alternate-buffer reset when needed. A 256KiB byte-bounded raw mailbox per pane with16KiB chunks overflows to reseed, never dropped bytes into a live parser. Accumulate bitsets; first damage arms one deadline against client presentation phase, at most4ms coalescing latency; no repeated idle ticks. Encode once per room publication, share immutable buffers. Ordinary frame work never acquires global sessions lock. Explicit implementation commitment: vendor the vt100/vte parser as needed to export/import a full parser snapshot, including incomplete CSI/OSC/UTF-8 state, and instantiate the watched mirror with mutation hooks. Antigravity reports upstream vt100::Parser lacks Clone; no existing Clone API is assumed. Formatted screen bytes are insufficient and are rejected as the bootstrap solution. Compile the ordinary parser with a no-damage policy and the room mirror with a dirty-row policy; snapshot/restore is control-plane only. Verify no extra runtime branch/callback/instruction on unwatched normal ingest; the fork does not license hot-path overhead.

**Numbers/measurement:** **budget** <=166.7us room CPU/pane/publication at60Hz (10ms CPU/s =1% of one core); includes extra parser, damage and encode. Ordinary session metadata lock hold p99<=100us; bootstrap <=1ms/pane separately recorded. Trace byte ingress→damage→publish timestamps plus CPU time, compare no-viewer baseline structurally and with profiler. Report separate per-pane parser CPU, damage CPU, encoder CPU, and per-room/client pack+decode columns; dividing or comparing all16-pane CPU to one-pane allowance is invalid. Use a fixed declared replay (2 dirty rows/pane/frame) and separately report full redraw and `yes` MB/s; unbounded input has no finite universal CPU guarantee.

**Fidelity check beside speed:** replay identical bytes into reference xterm and the room parser; require exact cell graphemes, widths, 24-bit colors, bold/italic/dim/underline/strikethrough/inverse, cursor position/shape/blink/visibility and alternate-screen state. Golden diffs after each cursor-only, attribute-only, scroll, wide-CJK, combining-mark and emoji mutation must show 0 unexplained changed pixels at matching native resolution. Blink must use matching phase-controlled tests. Current screen.rs loses required attributes and uses scalar-indexed text; its ScreenDump format is forbidden as the v2 fidelity source. Parser incompatibilities are release blockers, not permission to omit data. Rerun distance/oblique snapshots after scroll/resize; coalescing may skip intermediate state but never corrupt the displayed final state.

**Risks/proof test:** actual bridge internals and parser mutation hooks are not present in supplied reference. Atomic attach during split CSI/UTF-8, resize/output ordering, style-only/cursor-only damage, erase, scrolling, alternate screen, wide/combining cells and forced overflow must match a reference parser snapshot. Review rule: no session-table guard across `.await`, no nested room/session locks, no per-frame file I/O. Stall socket writers and prove other pane operations continue.

## 3. Ship a bounded binary room protocol

**Goal/deliverable:** **Decision 3: uncompressed, little-endian binary cell spans with dictionaries**, no JSON frame payload. **Decision 7: one in-flight frame plus replaceable latest state per viewer; skipped bases force an independent keyframe.** Room v2 uses `/ws/room/{id}`; legacy `/ws/wall` remains compatible but is unused by this client.

**Files/modules:** Hyperia `room/{protocol,stream}.rs`, route wiring and authorization; 3dterminal new room binary decoder replacing hot-path `hyperia/stream.ts`, `tab-stream.ts` and stream-source adapters.

**Wire commitment:** 32B frame header (magic u32, version u16, type u16, epoch u32, sequence u64, baseSequence u64, payloadBytes u32); 16B span header (source u32, row u16, startCol u16, count u16, flags u16, reserved u32). Each cell16B: graphemeId u32, foreground RGBA u32, background RGBA u32, attribute bits u16 (including bold/italic/dim/underline/strikethrough/inverse), width u8, reserved u8. Grapheme dictionary resets with epoch and uses length-prefixed UTF-8; explicit continuation cells and colors prevent scalar-index/column confusion. Source IDs address shared pane content; Rust layout maps any number of wall/desk surfaces to that source without duplicating cell payload. Metadata/control may use JSON off the frame path. Lossless cursor records include shape, blink and visibility; dictionary entries retain entire grapheme UTF-8 plus column widths. Underline styles/colors use explicit lossless extension records. Cursor/extensions and dictionary additions are separately counted. Keyframe partitions carry consistent epoch/revision and are swapped only when complete.

**Numbers/measurement:** **calculated**, established dictionary,16 panes x120 columns: 2 dirty rows each =32 spans x(16+120x16)+32 =**61,984B/frame;3.71904MB/s at60Hz**, or29.75232Mbps payload. Full40 rows =640 spans x1,936+32 =**1,239,072B/frame;74.34432MB/s at60Hz**, or594.75456Mbps. At30Hz halve rates. 1080p and4K use identical payload for identical grids; raster resolution does not multiply cell traffic. Full4K RGBA =33,177,600B/frame,1.990656GB/s at60,0.995328GB/s at30;1080p =8,294,400B/frame,497.664MB/s at60. Quote wire/WebSocket/TCP/TLS overhead and dictionaries separately in benchmark logs; these arithmetic numbers are not compression measurements.

**Fidelity check beside speed:** encode/decode must preserve every cell field and exact grapheme bytes; replay/keyframe/slow-viewer recovery must yield the same xterm golden at the same revision (0 unexplained pixel differences). Terminal and text-bearing image frames are lossless only: no JPEG/lossy WebP or chroma subsampling. Preserve RGB/alpha/color-space interpretation through upload. Dictionary overflow or insufficient glyph residency cannot substitute missing glyphs; chunk/resync or fail visibly. Test sharp one-pixel box edges and color emoji at the nearest and farthest specified views after reconnect.

Measured scratch evidence (2026-09-24): `node scratch/control-room-v2/cell-wire-bench.mjs`, Node v24.21.0, Linux x64 container, Intel Core Ultra9 285K (24 logical CPUs), 2,000 warmups +10,000 samples. Preallocated pack+decode for all16 panes: two-row frame61,984B median3.895us/p99 39.003us; full frame1,239,072B median95.539us/p99 668.621us. Process CPU across10,000 iterations69.482ms/1,347.408ms respectively. Established dictionary only; excludes VT/parser damage, allocations, socket, GPU and physical presentation. This is not a Rust CPU or end-to-end result. Rust check `rustc --version` failed because rustup has no configured default toolchain; no Hyperia build attempted.

Peer evidence audit: `scratch/control-room-v2/benchmarks.rs` and `benchmarks.txt` are Antigravity-provided artifacts, not rerun by Codex. The original Rust encoder copies a padded repr(C) header and patches offset28 despite payload_bytes residing at32 on8-byte-u64-aligned targets; it also replaces nondefault colors with green and omits most attributes/backgrounds. Its timings do not validate the specified wire or fidelity-equivalent speedup and are excluded from qualification evidence pending a corrected roundtrip. The parser timings are isolated peer-reported samples, not room-pipeline measurements. Step3 implementation must serialize every field explicitly LE and verify a decode roundtrip before benchmarking.

**Bounds/proof:** maximum binary message2MiB, WebSocket write buffer2MiB, one unacknowledged frame; one latest-state pointer plus dirty union. Slow ACK>100ms marks keyframe required; send/ACK stall>2s closes connection. Keyframes larger than2MiB are bounded chunks, one in flight. Sequence base must equal client's applied sequence; ACK only after apply. Cap dictionary64KiB then rotate epoch; enforce decoder lengths. Test fuzzed lengths/IDs, epoch changes, lost intermediate states, 8 viewers with1 deliberately blocked, 10-minute bounded RSS, reconnect with250ms full-jitter base capped8s. Raw input keeps per-event terminal-control authorization. Preserve authenticated read policy and same-origin endpoint discovery.

**WebCapture side budget (committed):** extend capture API to lossless PNG with alpha/color-space metadata, decoded to native-resolution RGBA and dirty-uploaded by WebGL2. Admit at most2 visible web sources at1920x1080 each, event-driven Electron paint damage with one in-flight capture/source and10Hz maximum publication; a damage-triggered100ms cap timer, no idle capture polling. Actual required projected resolution wins over rate: reduce cadence explicitly when over budget, never scale up low-res text or switch to JPEG. Request/source revision tags reject stale decodes. Full uncompressed upper-bound traffic for2x1080p at10Hz=165.888MB/s before PNG compression; measure actual encoded sizes and capture latency separately, never count it as terminal4K60 success. If lossless capture is unavailable, show an explicit unavailable source state until implemented; do not silently erase or run HTML through vt100. The mandate forbids old /ws/pixels JPEG for text-bearing pages.

## 4. Draw the flat room with dirty GPU updates

**Goal/deliverable:** **Decision 4: no server text rasterization (0 server glyph-cache bytes and0 server pixel blits); client vector-font rasterization at actual device pixel density with browser hinting/anti-aliasing and a cache keyed by font-file hash, style, grapheme and raster size. Decision 6: raw WebGL2**, instanced cells drawn into native-resolution per-surface framebuffers; `texSubImage2D` updates changed cell-data rectangles and new RGBA glyph atlas regions only. Use lossless RGBA to preserve color emoji. Match the pinned xterm font, fallback, metrics and custom box/block geometry. Textures have mipmaps plus maximum supported anisotropic filtering (qualification minimum8x) for angled/minified views; re-rasterize before magnification would exceed1:1, never enlarge a low-res font atlas. Dirty GPU rectangles update affected mip regions. Rust provides geometry/transforms/layout; the client executes them without assignment/lease authority.

**Files/modules:** 3dterminal `display/` new binary-cell GPU renderer and `scene/` thin raw-WebGL2 flat-room view of Rust geometry, transforms and hit IDs. Replace main.ts integration with view/controller modules. Delete curved UV/three.js/GLB-pivot dependencies, per-section `/ws/pane` sockets, TabStream outside leases, per-frame Canvas2D fillText painters, hardcoded :9800 websocket URL, 3s topology polling, and localStorage authority. Preserve flat-room controls, shared paint/pick transform, power/source isolation and numeric desk-height behavior; parity with the old curved theater is not the acceptance test. Font-cache misses may rasterize vector glyphs once; the deleted fillText path is per-cell per-frame drawing.

**Numbers/measurement:** **budget** 3840x2160 output,60fps sustained, client CPU decode/upload<=2ms/frame, GPU room render<=4ms/frame on declared target GPU. One2048x2048RGBA8 glyph atlas=16MiB base,21.33MiB with full mip chain; hard128MiB glyph residency, evict only unused generations. 4K RGBA surface framebuffer=31.64MiB base/42.19MiB with mips, shared for surfaces with identical content/density. Dimension from maximum projected pixel footprint xdevicePixelRatio, with 25% size hysteresis; reserve adequate density for perspective near edge. 76,800 cells in16x120x40 stress scene. Dirty cell upload61,440B plus metadata, full1,228,800B, excludes new glyph uploads; measure all atlas/FBO/mipmap costs too. rAF exists only while content/camera/animation/cursor blink needs presentation.

**Fidelity check beside speed:** front-facing untransformed surface must be pixel-identical to pinned `/ws/pane`+xterm at identical font files, fallback, theme, dimensions, DPI and deterministic cursor phase. Emit a diff image and list exact coordinates/attributes for every mismatch; no aggregate SSIM threshold hides wrong characters. Render box/block characters, truecolor gradients, CJK double-width, emoji/ZWJ, combining marks and all required attributes. At perspective views compare to the same high-resolution reference texture under the identical transform/filtering; evaluate legibility at ROOM.md's eye distances and minimum angular character size. Antialiasing or browser raster differences are currently unmeasured and explicitly not claimed identical. Any mismatch must be explained and corrected or explicitly reviewed as a difference; no 8x8 fonts, MSDF approximation, low-res upscaling or lossy text escape hatch. If budgets fail, batch/cache/optimize while retaining these fidelity gates.

**Risks/proof test:** font shaping/fallback, WebGL context loss, raw-renderer feature parity and physical readability. Establish a headless screenshot golden test BEFORE migration: flat wall actually visible, all desk monitors drawn, Unicode/color/cursor correctness, independent slot updates, front-face orientation and explicit source isolation. Instrument GPU timer queries/upload byte counters and browser performance traces; restoring context must request new epoch/keyframe. Legibility is a separate ROOM lane acceptance criterion;16-pane stress mode is not automatically an ergonomic operational layout.

## 5. Qualify the speed contract and merge the reviewed design

**Goal/deliverable:** reproducible benchmark report plus four explicit AGREE votes against the final revision. Implement only after this research plan is accepted. Integrate AUDIT/RENDER/ROOM evidence, preserve the committed seven decisions unless a measured result forces a documented revision. No claimed passing implementation tests in this research run.

**Files/modules:** Hyperia room benchmark/replay harness and trace points; 3dterminal render golden/performance tests; `docs/control-room-v2/{SIDECAR,RENDER,AUDIT,ROOM,PLAN}.md` evidence and review log. Scratch work stays under `/workspace/3dterminal/scratch/control-room-v2/` per container guardrails, overriding SWARM's `/tmp` suggestion.

**Numbers/measurement:** 10-minute4K60 runs with16 streaming panes, then8 viewers; record hardware, OS, browser/GPU, font, grid, ingress MB/s, chunk sizes, CPU time, RSS, drops, payload/wire bandwidth and latency histogram. Run cargo-build replay, bounded-rate `yes`, and full-screen TUI redraw trace separately. Acceptance: no missed presentation deadlines in10-minute4K60 run (36,000 expected frame slots when continuously dirty), <=1% one-core room overhead per active pane for declared workload, approximately0 idle CPU with0 polling wakes; report saturated stress failures, never hide them in averages.

**Fidelity check beside speed:** run the performance workloads with fidelity fixtures active and compare captured frames to xterm at matching content revisions; missing glyphs, attributes or cursor states invalidate the speed result. Deliver pixel diffs with 0 unexplained changed pixels for native views, plus perspective reference comparisons and human legibility checks at every specified seated/standing/farthest viewpoint. Record font hashes, DPI, camera transforms, filtering and color pipeline. A faster blurred/simplified run is a failed qualification. Web/text capture compatibility must also be lossless and tested separately; the current JPEG endpoint is not accepted for text-bearing surfaces.

**Latency contract:** <=16ms p99 PTY-write→physical wall pixel on localhost is the target; qualify on>=120Hz display hardware. **Calculated** a60Hz interval is16.667ms, so arbitrary-arrival p99 phase wait alone is about16.5ms; ordinary60Hz cannot robustly meet the physical16ms target. Budget at>=120Hz:4ms coalescing +1ms room/wire +2ms client/GPU +8.33ms refresh phase =15.33ms before actual panel-response accounting. A photodiode/high-speed capture correlated to PTY-write markers must verify the physical result; software presentation timestamps separately diagnose it. At60Hz report physical latency honestly and retain60fps throughput qualification; this is an explicit hardware condition, not a renamed latency metric. <=8ms stretch is unproven.

**Risks/proof test:** no measured CPU/GPU/physical-latency result yet; a source reference cannot prove these budgets. Rejection gates: any unbounded queue, guard across await, no-viewer ingest addition, lost parser sequence, clobbered source or unreported frame drops blocks acceptance. A benchmark payload encoder alone does not prove end-to-end performance. Record remaining unmet targets with observed values before approval, and never mark consensus from silence or retained-but-undelivered mail.
