# Hyperia bug log

Bugs found while using Hyperia and what was done about them. Newest first.
"Shipped in" is the first installer that has the fix; "unbuilt" means the fix
is committed but no installer has it yet.

| # | Found | Bug | Cause | Fix | Status |
|---|---|---|---|---|---|
| 22 | 2026-10-16 | Since ~16:00 the Electron↔sidecar link dropped every 2–4 min (link #32 by 18:36). Each drop cleared the sidecar's pane table (blank screen mirrors) and lost in-flight mail notices (5 today) | ~/.hyperia/lume/shell-logs.json had grown to 482 MB (1,104 shells, 6.5M lines; closed shells were never dropped). Every 45 s persist() cloned and serialized all of it under the lock that the Electron reader takes for every PTY chunk, then wrote it with a blocking call. The reader stalled past Electron's 15 s heartbeat timeout and Electron reconnected | Cap the store (400k lines, 200 shells, least recently written evicted, live writer kept); persist only when changed, serialize and write (tmp + rename) on a blocking thread outside the lock; trim an oversized store on load. 3 tests | Fixed, unbuilt |
| 21 | 2026-10-16 | Agents reading panes (terminal_screen / scrollback) got text with dropped letters ("s rver on p rt", "Fnd Egre") and then a blank screen for Magnificent Vole, though the pane showed text | The sidecar keeps its own screen copy via the vt100 crate. On a shrink vt100 keeps the TOP rows and clamps the cursor to the last row; xterm keeps the cursor's row and pushes the top into scrollback. After Vole's pane went 68→32 rows the copy was misaligned, and Claude Code's cursor-relative redraws landed on the wrong rows | On shrink, scroll the copy so the cursor row stays visible (xterm behaviour); 2 tests. Known gap: on grow xterm pulls lines back from scrollback and vt100 doesn't | Fixed (shrink), unbuilt |
| 20 | 2026-10-16 | Sticky "Elegant Cat" agent run (antigravity) failed after 17 s with "agent run ended with running" | The sticky runner's n8 poll treated any fired trigger with a status other than "ok" as finished-and-failed, including n8's in-progress "running", then deleted the trigger, cutting the run off | Keep polling while n8 reports "running"; only "ok"/"error" end it. Poll takes an injectable request for tests (2 new) | Fixed, unbuilt |
| 19 | 2026-10-16 | Kord's radio call "Stable Xerinae, open squelch problem, look at the logs" sat unread 10 min; nobody had touched the keyboard | Focus protected a pane indefinitely: Stable Xerinae was the selected pane in the front window, so its notices waited for a click elsewhere, exactly when Kord was away using the radio | Focus protects a pane only within 5 min of the last click or keystroke there (sidecar and main both); typing protection unchanged. Separate commit so it can be dropped | Fixed, unbuilt |
| 18 | 2026-10-15 | Ctrl-C (Kord's keypress and terminal_keys ) didn't stop hertzd in Fond Egret or lume in Yucky Fowl; the ^C keys came out at the pwsh prompt after the program was killed, one turning the next command into "c.	arget…" | The pane's console had ENABLE_PROCESSED_INPUT off (0x01F0 while hertzd ran), so ^C was a queued keystroke, not CTRL_C_EVENT. PSReadLine restores the mode it found at each prompt, so once a raw-mode program dies without restoring the console every later command inherits it. Not specific to terminal_run; a fresh split worked | pwsh integration turns Ctrl-C processing back on before each prompt (verified in a forced-raw console: 0x01F0 → 0x01F1). Workaround for an open pane: run `[Console]::TreatControlCAsInput = $false` once (confirmed by Stable Xerinae). The leak itself was the hertz TUI leaving raw mode only on clean exit, fixed in hertz 41cbcbf | Fixed, unbuilt |
| 17 | 2026-10-15 | Radio call "India Papa, look at Sharp Minnow, it's not working" was stored as mail for Sharp Minnow, an ssh shell, where nothing can read it | Hyperia accepts mail for any live pane; for a shell the notice is skipped, and the sender isn't told the recipient can't read mail | Proposed: refuse (or flag in the reply) mail to a pane that isn't running an agent, so hertz can fall back | Open |
| 16 | 2026-10-14 | Minor Canid's PR breakdown sat unread in Magnificent Vole's inbox 20+ minutes; nobody had typed there and its tab wasn't showing | The sidecar counted a pane as "human focus" if it was the active pane of its tab in the focused window, ignoring whether that tab was the one showing (Electron's check does require it). | 15 | 2026-10-14 | Radio mail to Ordinary Penguin sat with no notice for 6+ minutes; Kord wasn't in the pane | Every byte xterm sends counted as human typing, including the mouse-position reports a mouse-tracking program (Claude Code) gets while the pointer merely crosses its pane — bursts every ~7 ms in the log. | 14 | 2026-10-14 | Deck made idle Bobcat and Stable Xerinae look like they were downloading | Host agents without the counting proxy get "io-approx" network: their process tree's total I/O, disk included (Windows has no per-process network counters without admin).
