# Delivery implementation contract

Coordinator accepts the need for persisted operation state and explicit idempotency keys. Begin a standalone `sidecar/src/delivery.rs` with deterministic tests; do not edit main.rs/bridge.rs/perms.rs yet, integration follows shared review. Use nuts tools for file work. Never include credentials in reports.

Operation lifecycle: awaiting_approval -> queued -> submitting -> submitted, failed, denied, expired, cancelled; recovery turns submitting into indeterminate (never replay blindly), and awaiting_approval/queued into expired pending a fresh authorized submission. The record must preserve caller principal, target pane incarnation, operation kind, validated payload and explicit submit bool, timestamps/expiry, idempotency key and delivery outcome. Transport does not claim agent acknowledgement. Do not append Enter to input whose submit=false.

Provide a thread-safe store with an injectable file path and serialized atomic persistence before reporting acceptance. A JSON operation journal/snapshot is authorized; this is separate from redesigning existing mail JSONL. Return IO errors. Bound payload and pending queue size. Generate collision-resistant IDs locally. Idempotency is requester-scoped; same key with different target/payload must conflict rather than silently reuse. Claiming for submission must be atomic and happen only from queued state; never permit cross-requester consent to release another operation. Bind exact consent request IDs when available. A grant covering a pane can release that requester's waiting operations only; IDs and requester/target must be checked together.

Expose clean methods (your choice of names) for create/get-for-caller, associate approval, resolve approval, claim, complete, cancel, expire/recover. Unit tests need two callers/one pane, two pending ops, fast/late approval with a single executor, denial, duplicate resolve, idempotency replay/conflict, persistence failures and reopen/recovery. No real transport needed for standalone state tests. Tests create any filesystem fixtures under /workspace, not /tmp. Coordinator currently runs cargo test baseline; avoid cargo-lock contention by reporting module ready before whole-crate test.

Write implementation status and API examples to plan/ermine-implementation-status.md. Implementation of existing held-action endpoints will use this store after the shared API contract is settled.
